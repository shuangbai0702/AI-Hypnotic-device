## 实际验证证据

- 完整 Node 回归：原 49 项加 23 项，72/72；Node 24.16.0 和 24.22.1 各通过。独立的最新版 DSH 依赖环境再运行 72/72，避免只依赖开发副本。
- 实际 Windows EXE 安装、卸载及重装：DSH `0.1.7-rc.2`、`0.2.0-rc.1`、`0.2.0-rc.2`、`0.2.1-rc.1`、`0.2.1-rc.2`。前四个还在服务运行时重装，验证停止及重启目标身份保护。最新版通过实际健康失败回滚后重装。卸载核对原宿主文件字节；合成凭据哨兵保持原样。
- 各版本真实请求链：原生 Web 创建会话 → 本地模型响应 → 压缩原用户消息 → 编辑活动摘要及保留的助手旧回复 → 下一轮捕获请求确认新内容生效且旧内容消失 → 第二次压缩 → 服务重启 → 再次捕获验证持续生效 → 连续三次移出上下文 → 原生历史与分页仍可读取 → 八个并发上下文读取结果一致 → 原生会话格式及压缩关系校验通过。每轮包含三个真实 HTTP 模型请求；使用隔离本地模型桩，无付费服务调用。
- 归档原消息只读与活动摘要可编辑的边界在上述链路验证。编辑旧助手回复保留，不因原用户消息已压缩而禁用。
- 实际健康失败：仅修改测试安装包，让插件加载时抛错。EXE 检出插件服务未就绪，停止自身启动的测试进程，恢复全部受管宿主文件和配置，清除待恢复标记；重试正常包后完整链路及卸载通过。错误不能被根页面 HTTP 200 掩盖。
- 性能探针：Node 24.22.1 下旧解码器对 3 帧产生 6 条，新解码器产生 3 条。新解码加 JSON 解析，100/1000/10000 帧分别约 1.874/11.469/139.195 ms；该进程峰值 RSS 约 164 MiB。Node 24.16.0 的 10000 帧约 138.289 ms。仅为本机合成负载，不是所有真实会话的性能保证。
- Windows PowerShell 5.1 构建 EXE；安装包逐文件 SHA-256 校验。上述 EXE 验证通过程序参数入口执行，不冒充安装界面点击。

可复现实验入口：`npm test`、`tests/windows-discovery.ps1`、`tests/windows-installation-e2e.ps1`、`tests/windows-health-rollback.ps1`、`tests/native-session-e2e.mjs`。后三者只允许显式隔离目标，拒绝受保护端口；参数和要求见测试文件。测试专用缓存、配置、令牌日志及实际会话不纳入发布文件。

## 计划偏移与边界

1. **仍需三个宿主适配点。** 调查过原生工厂/生命周期：网页创建的驻留 agent 没有满足编辑要求的公开闲置释放入口。保持由原所有者释放并重开，使用逐构建散列和锚点约束，没有通过删除检查扩大支持。后续原生接口改变需重新适配。
2. **旧离线写命令收敛为只读检查。** `log-rewrite.mjs` 原本的编辑、删除、插入、修复、恢复路径绕开原生写租约。为避免旁路写入，现明确拒绝这些命令；网页编辑能力保留。拒绝路径测试确认源文件不变。这是有意的维护接口兼容变化。
3. **首次原生 profile 初始化在受管文件事务之前。** 失败时回滚插件和宿主变更，但可能保留 DSH 自行生成的空白 profile/日志；不递归删除可能被其他程序使用的新目录。凭据文件不属于安装事务目标。
4. **自动发现有边界。** 扫描常用进程、PATH、npm/版本管理器及有限缓存目录，不遍历全部磁盘。其他进程的自定义环境不能可靠反推；已有安装记录优先，多候选由用户选择，高级项可校正。自定义启动参数不会被静默丢弃，安装器会保留进程并提示先手动关闭。
5. **环境限制没有改写为成功。** 当前计算机控制工具没有可用浏览器或应用表面；未验证安装器按钮、真实浏览器 DOM/视觉和普通双击启动。已验证 HTML/静态资源及原生 RPC，不能替代视觉验收。未连接服务器，未做 Linux 验收、真实账号接口验证或系统级断电/磁盘满测试。
6. **账户截图仅有状态解释。** 原生 DSH 可在本地有登录凭据、资料请求失败时显示“账号资料暂不可用”。安装/卸载测试的合成凭据未变化；没有对方日志，不能断言插件损坏认证，也不能保证其账户网络恢复。没有删除或重写真实凭据。
7. **保留发布门槛。** 当前源码改进和本地候选包尚未更新公开 Releases。没有将旧版 47/49 或本轮 72/72 描述为全部发布验收完成；`Killed` 的原服务器原因也未确认为 OOM。
